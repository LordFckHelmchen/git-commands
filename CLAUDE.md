# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A personal dotfiles/tooling-config repo. It holds no application code — the "product" is the set of
config files that `symlink_files.py` links into the user's home directory. Editing a tracked file in
this repo immediately changes the live shell/git/editor behavior on any machine where the symlinks
exist (no re-run needed; re-run only after *adding* a file).

Primary target platform is Windows with Git Bash; Linux is a supported secondary (`is_linux` /
`is_windows` branches throughout `bash/.bash_aliases`).

## Commands

```bash
# Install/update symlinks into $HOME (Windows: needs admin shell or Developer Mode)
python symlink_files.py                          # bash/* + git/.gitconfig (+ cmd/* if clink installed)
python symlink_files.py --link_starship_config   # additionally themes/starship.toml + cmd/starship.lua
python symlink_files.py --link_git_prompt        # instead: bash/git-prompt.sh (mutually exclusive with above)
python symlink_files.py --force                  # overwrite existing destinations

# Lint / format everything (this is the only "test suite"; CI runs exactly this)
prek run --all-files          # alias: pra
prek run <hook-id>            # single hook, e.g. `prek run shellcheck`, `prek run ruff-check`
prek install                  # install commit-msg + pre-commit shims
```

There are no unit tests. Correctness gates are `shellcheck`, `shfmt`, `ruff`, `rumdl`, `actionlint`,
`gitleaks` and the conventional-commit linter, all defined in `.pre-commit-config.yaml`.

`prek` is used instead of `pre-commit` (Rust drop-in). The config file keeps the
`.pre-commit-config.yaml` name for upstream compatibility.

## Architecture of the shell config

Load order matters and functions are shared across files, so the four bash files are one unit:

1. `bash/.bash_profile` → sources `~/.profile`, then `~/.bashrc`.
2. `bash/.bashrc` → defines the logging layer (`log_debug/info/warn/error`, `log_message`,
   `log_done`) and `source_if_exists`, then sources `~/.bash_aliases`, then completions, then the
   untracked local override, then calls `deduplicate_path`.
3. `bash/.bash_aliases` → defines `is_command`, the PATH helpers (`is_on_path`, `remove_from_path`,
   `prepend_to_path`, `deduplicate_path`), OS predicates, git/gh helpers, tool PATH setup
   (pyenv/poetry/adr-tools), `add_completions`, and the `updateAll`/`updateTools`/`updateRepos` trio.
4. `bash/.bash_completion` → sources everything in `$BASH_COMPLETION_FOLDER`
   (`~/.bash_completion.d`), generated by `add_completions`.

Consequences to respect when editing:

- `.bashrc` calls `is_command` and `deduplicate_path`, which live in `.bash_aliases` — that file must
  stay sourced before those call sites.
- Use `log_*` rather than bare `echo` for diagnostics; log level is `$BASH_LOG_LEVEL` (default `INFO`).
- Guard every tool-dependent alias/function with `is_command <tool>` and emit `log_warn` in the
  `else` branch. This is the established pattern for all of `prek`, `uv`, `gh`, `starship`, etc.
- Add directories to PATH only via `prepend_to_path` (it de-dupes and silently skips missing paths).

Machine-specific values never go in this repo. They belong in untracked overrides:
`~/.bash_config_local.sh` (env vars, aliases; sourced by `.bashrc`) and `~/.gitconfig_local`
(user name/email; `[include]`d by `git/.gitconfig`).

### Mirroring bash into Clink (CMD)

`cmd/*` mirrors the bash key bindings, aliases, and update functions for CMD via Clink. It must be kept in sync with
`bash/.bash_aliases`:

- `cmd/.inputrc` mirrors the bash key bindings.
- `cmd/clink_aliases.cmd` mirrors the single-line aliases as `doskey` macros. `cmd/starship.lua`
  (linked only with `--link_starship_config`) loads them by scanning the file line-by-line and only
  registers lines of the exact form `doskey <name>=<body>` — no line continuations, no multi-line
  bodies.
- `cmd/update_all.cmd` mirrors the multi-statement functions (`updateAll`/`updateTools`/`updateRepos`). `symlink_files.py`
  links it into `%LOCALAPPDATA%/clink`, and `clink_aliases.cmd` invokes it via `doskey` macros.

When you add or change something in `bash/.bash_aliases`, adapt the Clink config to match:

- One-line alias → add/update the matching `doskey` line in `cmd/clink_aliases.cmd`.
- Multi-statement function → add/update a subroutine in `cmd/update_all.cmd` (or a new batch script)
  and expose it via a `doskey` macro in `cmd/clink_aliases.cmd`.
- New key binding → update `cmd/.inputrc`.

## Contribution conventions

Conventional commits are enforced on both commit messages (commit-msg hook) and PR titles
(`validate_pr_title.yml`). The allowed types and scopes are duplicated in two places and **must be
kept in sync** — `.pre-commit-config.yaml` (`conventional-precommit-linter` args) and
`.github/workflows/validate_pr_title.yml`. The latter is the ground truth for types and scopes. Both files carry a
`Keep in sync with ...` comment. Commit scopes mirror top-level directories in this repository, plus `deps`, `deps-dev`,
`prek`, `starship`, `nushell`, `xonsh`

Releases and `CHANGELOG.md` are generated by release-please (`release-type: simple`) from commits on
`main` — never hand-edit `CHANGELOG.md` (it is also excluded from `rumdl`).

GitHub Action versions are pinned to full SHAs with a trailing `# vX.Y.Z` comment; prek hook `rev`s
are frozen SHAs with `# frozen: vX.Y.Z` (maintained by `prek autoupdate --freeze` in
`prek-hooks-update.yml`). Preserve that style when touching either.

## Python style

Standalone scripts, no package, no dependency manifest. Ruff runs with options configured in the root-level `ruff.toml`.
Notable consequences: full numpy-style docstrings with `Parameters`/`Raises`/`Yields` sections are required,
`TODO` comments are rejected (`FIX` rules), and `print` is allowed. Scripts carry an SPDX header
(GPL-3.0-or-later) and `python/estimate_import_time.py` uses PEP 723 inline metadata for `uv run`.
